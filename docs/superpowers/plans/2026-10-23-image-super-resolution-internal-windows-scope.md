# Windows 内网增强 Worker：精简安装与恢复范围

本页是 Windows 内网部署的最新范围，覆盖此前方案中更严格的安装和恢复前置要求。目标环境为已有管理员维护的内部 GPU 机器；开发以安装成功、稳定超分、异常可恢复和数据保留为重点。

## 保留的必要行为

- 使用已有 Windows 服务机制完成安装、升级、启停和卸载；卸载默认保留任务数据。
- 校验配置、目标目录、端口与引擎是否可用，只操作项目自己的服务和目录。
- 内网 HTTP 与 API Token；同一安装避免并发升级或恢复。
- 升级前保留完整健康备份。恢复前确认服务停止、端口可用、备份可读且数据库检查通过；开始修改前核对完整当前数据，避免覆盖新增任务。
- 复用现有恢复事务归档原失败数据、恢复健康数据并启动服务。任一步失败保留双方数据和诊断，不自动删除数据库或循环重试。
- 实机验证服务自启动、真实 GPU 超分、任务保留，以及常见升级和恢复失败处理。

## 不再作为本期门槛

不继续扩展针对不可信本机管理员的攻击防护、逐文件 ACL/元数据/身份封存、全系统 SID 空集证明、历史调用者身份追认或多层独立恢复证明材料。权限配置和兼容矩阵不扩展；内网不强制证书。已做的相关技术试验保留为历史，不计为必须补齐的 M3 验收项，也不标记成实机通过。

必要的文件操作仍固定目标，保留备份并检查复制、数据库和启动结果。实现简化不改变任务数据保留、错误日志和失败状态处理。

## 下一实施切片

1. 复用 `Recover-Worker.ps1` 和现有恢复主体，为可信内网管理员提供直接恢复调用，核心输入为原安装记录、健康备份、凭据、新归档目录和期限。所需摘要由程序读取并记录，避免操作者准备完整证明链。
2. 准入检查只解决正常运维问题：操作并发、服务仍运行、端口冲突、备份损坏、当前数据已变化或数据库无法读取。复制与交换前后按阶段验证结果，避免每一步重复扫描全部数据和代码树。
3. 删除尚未接入使用的复杂证据准备入口及配套死代码，保留已经稳定使用的安装和运行行为。仅测试新直接恢复入口、相关旧流程及真实服务恢复。
4. 在现有内部 GPU 测试机完成实际恢复和剩余功能验收，整理安装包、使用说明和问题诊断。

## 当前实施进度

内网管理员直接恢复入口已实现，复用原 `Recover-Worker.ps1`：

```powershell
.\Recover-Worker.ps1 `
  -Receipt '<安装记录路径>' `
  -BackupReceipt '<健康备份记录路径>' `
  -RecoveryRoot '<同卷的新归档目录>' `
  -CredentialFile '<已有凭据文件路径>' `
  -TimeoutSeconds '180'
```

程序自动读取原失败操作和摘要；操作者无需另行准备失败证明文件。该入口适用于服务已停止、当前完整数据与健康备份内容一致的升级启动失败；数据已有变化时拒绝覆盖，保留现场。

已移除未接入使用的独立证明准备入口、系统 SID 枚举及其专用 Store 分类和测试；旧十参数恢复入口继续兼容。源代码已独立静态审查，恢复定向回归 4 项、Store 回归 80 项、类型检查和构建通过；其中新入口包含 11 个事务与失败保留场景。这些本地测试未替代真实 Windows 服务、SQLite、HTTP 和 GPU 验收。

测试机已完成一次独立真实恢复：健康旧版本启动成功，原十三个任务完整保持，七十八份历史原始记录、十三张原图和七个外部源文件核对通过；十二份历史结果完整下载并匹配摘要，共约 140 MB。失败归档与原健康备份均已读回验证。

新启动实例的一次 GPU 自检已通过，实际输出 5016×5016 PNG，并恢复为 `ready=true`；后续完整下载也通过摘要校验。该结果证明本次简化入口能完成真实恢复，不表示此前升级启动错误的根因已确定。M3 仍有运行中恢复、维护与卸载等余项，以及最终安装包交付，不因本次通过提前标完成。
