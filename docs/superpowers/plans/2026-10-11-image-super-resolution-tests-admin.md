# AI 高清增强：M4 管理员后台测试用例

关联方案：[图像超分接入 SOP](2026-10-10-image-super-resolution-integration-plan.md)第 9 节。本文定义“AI 高清增强”管理员面板及其后端配置契约的验收，当前API为`/api/admin/image-enhancement`；规格存在不代表全部业务组合断言已通过，实际状态以逐项证据为准。

共 12 项。当前分轮证据及未完成组合子项见[M4 实施记录](2026-10-23-image-super-resolution-admin-config.md)：M4配置开发和测试发布已完成，配置／权限、真实 PostgreSQL、HTTPS、桌面与提示可读性、类型构建、独立复审及最终新构建API真实样图链路分别通过，实际测试页面已复核，待用户确认。与 M5 相交的任务／原图／资产子项仍待组合验收，不将整项统一标成通过。执行状态、版本、结果和证据统一登记到主测试索引。P0 为对应能力上线阻断项；P1 为次优先级。只覆盖桌面操作与相关权限契约，不增加手机端测试。

首批远程 API 验收使用已交付的模式。本机 CLI 的专属参数在该适配器交付后执行，不把尚未交付的本机模式、SSH、API 服务账密或 mTLS 列为首批远程 API 上线阻断项。未交付能力不得以可用选项呈现。

## 数据与证据约定

- `F01`：1254×1254 的 PNG 原件，原生尺寸不足请求的 4K。保留字节摘要，比较原图回退与样图执行结果时使用同一原件。
- `F16`：受控 worker 响应集合，至少包含健康可达、鉴权失败、引擎缺失、GPU 不可用和样图失败。健康可达不等于具备实际推理能力。
- 准备管理员账户与无管理权限的普通账户，均使用隔离的验收数据。接口名称以实际实现为准；直接请求用于核对后端权限，不通过前端隐藏代替拒绝校验。
- API 临时密钥在实际执行时于内存生成，不写入本文、素材、截图或测试报告。需要验证泄漏时，由执行器只输出命中计数和字段位置，不输出密钥或完整认证请求。
- 证据保留版本、时间、任务标识、配置版本、脱敏阶段状态和必要截图；内部地址、系统账户、真实路径、凭据与信任材料不得进入公开交付文档。
- “配置意图”与“执行就绪”分别断言；只在所选模式的配置、身份、引擎/模型和真实样图检查通过后允许首次启用。

### SR-M4-01 无 GPU 默认关闭并允许先配置检测（P0；桌面 UI/权限契约）

**前置/数据**：使用完全没有 GPU、Vulkan、超分模型及增强 worker 的应用部署；管理员首次进入面板；使用 F01 验证普通生图原件交付。

**步骤**：

1. 启动主应用，打开面板，确认初始开关和就绪状态。
2. 在开关保持关闭时选择已交付的 API 模式，保存连接配置并执行检测。
3. 保持增强关闭，完成一次受影响普通生图流程，刷新后查看及下载原件。
4. 让连接检测返回 F16 的不可用结果，确认仍可修改和重新保存配置。

**预期结果**：默认关闭，主应用启动不下载模型、不初始化 Vulkan、不探测本机引擎，不依赖 worker 健康。管理员无需先开启即可配置和检测，检测失败不会形成无法配置的循环。普通生图可用，原件保持实际尺寸，增强记录为关闭跳过，不以普通插值伪装增强成功。

**证据**：脱敏启动及依赖记录、初始/检测失败面板截图、配置保存结果、原件摘要与尺寸、跳过原因。

### SR-M4-02 调用方式条件字段与未交付选项隔离（P0；桌面 UI/权限契约）

**前置/数据**：管理员面板；API 模式已交付。本机 CLI 专属分支在 M6 交付后执行；准备两种模式独立配置草稿。

**步骤**：

1. 选择 API 模式，检查服务地址、专用访问密钥、TLS 信任和可用模型字段。
2. 本机模式交付后选择本机 CLI，仅填写引擎、模型及工作目录，不填写地址或密钥，保存有效配置。
3. 在两种模式间切换并提交，检查实际提交的字段及配置解析结果。
4. 检查调用方式及认证下拉选项，尝试提交未交付的 SSH、mTLS 或服务账密模式。

**预期结果**：按调用方式展示字段；本机 CLI 不要求网络凭据，API 不把本机目录解释为远端参数。隐藏字段不随当前模式误提交、校验或改变认证含义；已保存的其他模式配置若保留，须独立隔离。未交付选项不显示，后端也拒绝对应模式，不静默回退到另一方式。

**证据**：条件表单截图、脱敏提交字段清单、按模式解析结果、未交付模式拒绝结果；本机未交付时主索引登记该分支待适用。

### SR-M4-03 管理权限覆盖后台接口（P0；桌面 UI/权限契约）

**前置/数据**：管理员、普通用户和未登录会话；隔离配置；无真实密钥的测试输入。

**步骤**：

1. 管理员读取及保存配置，执行连接、能力与样图检查，修改开关。
2. 普通用户访问面板并直接请求对应读取、保存、检查、清除凭据及开关操作。
3. 未登录会话重复相关请求；核对普通创作页面的任务响应。

**预期结果**：仅管理员可操作增强管理配置。普通用户和未登录请求由后端拒绝，不泄露配置细节、密钥存在之外的敏感材料或检测结果；拒绝不改变配置版本，也不触发样图推理。普通创作页面不获得管理凭据或高级执行参数。

**证据**：按身份整理的脱敏权限矩阵、拒绝状态及错误类别、操作前后配置版本、样图任务计数和普通任务响应字段清单。

### SR-M4-04 凭据加密、不回显与更新语义（P0；桌面 UI/权限契约）

**前置/数据**：API 模式；执行时生成两个不同临时密钥；可检查隔离配置存储的脱敏结果；清除操作具有明确入口。

**步骤**：

1. 保存第一个密钥，刷新面板、重新读取配置，检查持久化字段。
2. 保持密码框为空或不提交密钥字段，修改非敏感配置并保存，再验证原密钥仍可鉴权。
3. 明确替换为第二个密钥并保存，确认生效的凭据引用或版本变化。
4. 使用明确清除操作，刷新并重新执行鉴权检查。

**预期结果**：ZEB 凭据使用既有加密机制持久化，读取接口和密码框只表示“已配置”，不返回明文、掩码伪值或可用于请求的密文。空白未提交保留原值；替换才更新；明确清除后状态为未配置并使旧就绪结果失效。清除不显示成功就绪，也不在已启用故障期间恢复插值补尺寸。

**证据**：存储加密结构及不可明文匹配结论、脱敏读取字段、凭据版本变化、保留/替换/清除后的鉴权与就绪状态。

### SR-M4-05 凭据不进入任务、日志和导出（P0；桌面 UI/权限契约）

**前置/数据**：含临时密钥的 API 配置；F16 鉴权失败与引擎错误；准备配置、任务及调用记录的实际支持导出入口。

**步骤**：

1. 分别触发配置保存、成功检测、鉴权失败、样图失败及普通任务回退。
2. 查看管理员调用详情、普通用户任务详情、任务持久记录、错误信息与现有日志/导出。
3. 使用内存中的临时值检查敏感内容是否泄漏，仅保留命中计数与位置。
4. 提交包含 URL 用户信息或查询凭据的地址，检查配置是否拒绝这种凭据携带方式。

**预期结果**：访问密钥、Authorization 头、未脱敏异常上下文和完整信任/私钥材料不出现在任务 JSON、接口响应、普通日志和导出中。任务只冻结受控凭据引用或版本，不复制明文。地址禁止内嵌凭据，错误展示不会将其原样打印；可观测信息仍能区分失败阶段和原因。

**证据**：泄漏检查范围与零命中结论、允许字段清单、脱敏错误样例、带凭据地址的拒绝结论。

### SR-M4-06 按模式分层检测与明确诊断（P0；桌面 UI/权限契约）

**前置/数据**：F16；API 使用受信任及不受信任的测试服务身份；本机分支在 M6 交付后准备路径缺失、权限不足和模型缺失情形。

**步骤**：

1. API 模式依次触发不可达、TLS 身份不可信、鉴权失败、引擎缺失、GPU 不可用和正常能力响应。
2. 检查每次检测的阶段、原因、时间、执行模式与最终就绪状态。
3. 本机模式交付后，依次检测错误路径、运行身份权限不足、引擎缺失及模型缺失。

**预期结果**：API 明确区分连接、服务身份、认证、引擎/模型/GPU；不以关闭 TLS 校验绕过失败。本机从实际生成 worker 的身份及文件系统检查路径/权限，不执行无关网络认证检测。失败阶段停止向“就绪”推进，显示可操作的原因，不笼统误报为网络错误；诊断信息脱敏。

**证据**：参数化结果矩阵、各阶段与检测时间截图、TLS 拒绝证据、实际执行身份一致性结论；本机分支登记适用版本。

### SR-M4-07 首次启用必须经过真实样图（P0；桌面 UI/权限契约）

**前置/数据**：开关关闭；F01；F16 健康可达、鉴权失败、样图失败与完整成功状态；隔离且真实可推理的 GPU 执行环境只在实际执行本例时准备。

**步骤**：

1. 仅让端口或健康检查成功，尝试开启；再让认证和能力通过但样图未做，重试开启。
2. 让真实样图失败，尝试开启并查看阶段错误。
3. 使用与业务相同的执行身份、容器/进程环境、连接档案和所选模型运行 F01；核对输入、推理和交付尺寸。
4. 完整检查通过后开启并保存，刷新状态。

**预期结果**：端口、健康接口及模拟成功均不能单独作为增强可用或首次启用证据。失败时配置仍可保存，开关不进入首次已启用状态。真实执行成功且输出完整解码后才允许开启，结果明确记录真实执行环境和三组尺寸；不把现有 CLI 手工小样当成本次后台自检通过。

**证据**：启用门禁结果、各次就绪状态、真实样图任务标识及脱敏阶段记录、输入/输出摘要和解码尺寸、保存后面板截图；mock 与真实 GPU 证据分别标识。

### SR-M4-08 配置变化使旧就绪结果失效（P0；桌面 UI/权限契约）

**前置/数据**：已有完整检测并就绪的配置；准备每次只改变一个字段的参数化数据。

**步骤**：

1. 分别变更调用方式、本机路径/目录、API 地址、认证方式、凭据、TLS 信任和默认模型；只执行当前已交付模式的字段。
2. 每次保存后查看就绪状态、检测时间及所属配置版本，再尝试依赖旧检查开启或派发新增强任务。
3. 对新版本重新完成必需检查，确认就绪状态更新；重新保存完全相同配置，检查版本与检测归属。

**预期结果**：影响执行身份、连接或模型的变更立即失效旧就绪证明；旧检测时间不能冒充新配置通过。新配置未就绪时不派发未验证增强，原图路径仍可用。重新检测绑定新配置版本；等值保存不得错误借用其他配置的就绪记录。已启用时配置意图与待检测状态分别显示。

**证据**：字段变更矩阵、配置/检测版本关联、旧检查失效截图、新任务路由结论和重新检测记录。

### SR-M4-09 默认模型受真实能力白名单约束（P0；桌面 UI/权限契约）

**前置/数据**：API 鉴权后的受控能力响应；本机分支交付后使用受控模型目录；含有效模型、已移除模型、未知模型和错误倍率的参数化输入。

**步骤**：

1. 获取可用模型，核对后台展示的模型标识、版本和原生倍率。
2. 在界面及直接保存请求中选择未知、已移除或不符合返回能力的模型。
3. 将能力响应置为未鉴权或无模型，刷新列表并尝试样图/启用。
4. 保存有效模型后变更远端能力，检查下一次检测是否识别不匹配。

**预期结果**：模型来自受控目录或鉴权能力接口，后端校验白名单及实际能力，不把任意输入当引擎参数或文件路径。无有效模型时不得就绪/首次启用，不静默替换模型或假报倍率。默认模型变化重新验证，已冻结任务仍使用自己的模型策略并按执行结果如实报告。

**证据**：脱敏能力列表及模型映射、无效保存的拒绝类别、无模型状态、能力变化后的检测与任务策略记录。

### SR-M4-10 配置热更新与任务快照冻结（P0；桌面 UI/权限契约）

**前置/数据**：两个可验证的隔离连接档案或模型策略；任务 A 已入队或增强中；准备保存后创建任务 B。

**步骤**：

1. 记录应用与 worker 运行实例、任务 A 的冻结配置及远端 job 归属。
2. 管理员保存并验证配置版本 2，无需重启应用；随后创建任务 B。
3. 查看 A、B 使用的连接档案、执行模式、服务身份、模型策略及凭据引用。
4. 轮换凭据或更换端点，核对旧任务恢复/查询行为。

**预期结果**：有效配置保存后对新任务生效，无需重启容器；A 不因后台更新而变更冻结策略，B 使用新版本。凭据只按受控引用/版本解析，不进入快照明文；旧凭据被吊销时明确报告认证失败并保留原图，不能据此擅自终止远端任务。更新同服务的有效凭据后可查询原任务；服务身份变化时阻止错查，不冒用新服务身份。旧 job ID 不发送到新端点，配置更新不重新生成原图、不重复提交增强。

**证据**：保存前后实例身份、A/B 脱敏快照与任务事件、端点/job 归属检查、凭据轮换后的明确状态及生图/增强提交计数。

### SR-M4-11 已启用临时不可用时保留意图并恢复（P0；桌面 UI/权限契约）

**前置/数据**：已通过首次检查并启用的 API 配置；F01；F16 不可用、鉴权失败、GPU 不可用和服务恢复状态。

**步骤**：

1. 在已启用配置下模拟受控临时故障，提交受影响任务并查看后台与前台结果。
2. 刷新面板，核对开关意图、就绪状态、具体故障和最近检测时间。
3. 恢复服务并完成必要检测，提交新任务，查看此前任务的资产及状态。

**预期结果**：保持管理员“已开启”的配置意图，同时展示执行不可用；原图仍能查看和下载且保留真实尺寸，不自动插值冒充 4K。恢复后新任务可使用增强；此前已冻结或交付任务不被自动改写，不重新生图、不自动覆盖用户后续编辑。需要重试时只重试增强并遵循原任务身份与策略。

**证据**：故障/恢复面板截图、任务跳过或失败原因、原图尺寸及摘要、恢复后新任务增强阶段、旧任务资产与事件前后对比。

### SR-M4-12 关闭开关不取消运行任务或卸载服务（P0；桌面 UI/权限契约）

**前置/数据**：已启用并就绪的 worker；任务 A 已进入增强，任务 B 尚未创建；管理员具备独立的明确取消操作时才验证取消分支。

**步骤**：

1. 在 A 运行时关闭增强开关并保存，观察 A 与远端服务状态。
2. 创建 B，核对其增强路由及原件交付。
3. 刷新页面并查看 A 的冻结策略、已交付资产及下载/继续引用身份。
4. 若明确取消操作已交付，单独对另一运行任务执行取消，核对与关闭开关的行为区别。

**预期结果**：关闭只影响后续任务策略，A 按冻结策略完成，不因关闭自动取消、重发生图、撤回交付或替换编辑基线；B 以关闭跳过增强并交付原件。开关不自动卸载、启停已部署 worker 或安装模型。明确取消是独立操作，保留原件并有独立事件，不由开关动作隐式触发。

**证据**：A/B 冻结策略及阶段事件、worker 运行状态、关闭后的跳过原因、资产引用与下载摘要；取消分支的独立操作记录。
