## 使用流程

后台“上游配置 → AI 高清增强”中，先保持关闭，填写服务根地址、专用 Token 和请求超时，保存后检查连接。模型只来自鉴权后的 Worker 能力接口。选择默认模型并保存，再执行样图自检；样图完整下载、摘要、原生倍率和像素解码均通过后，首次开启才可保存。

首批只显示已交付的远程 Worker API。内网支持 HTTP＋Token；HTTPS 使用系统证书或显式 CA，仍验证地址／服务名称，不提供关闭证书校验。没有 GPU 的 Web 服务器无需安装或启动 GPU 运行库；保存配置和关闭增强均不启动远端服务。

Token 留空保留，输入新值才替换，清除使用独立确认操作。服务端使用既有 AES-GCM，GET 仅返回已配置状态，不返回 Token、密文或 CA 正文。服务地址禁止用户名密码、查询串和片段。管理员 API 为 `/api/admin/image-enhancement`，GET 读取，PATCH 保存，POST 按 `connection/sample` 检查；统一 `system.manage` 与当前 Session，无二次密码挑战。

## 配置与运行边界

- 配置修订号覆盖执行字段与开关意图。地址、凭据、信任、默认模型或超时变化使旧检测失效；仅切换开关推进修订并保留同一执行配置的有效样图，等值保存保留原修订。并发保存或迟到检测返回冲突，不能覆盖新配置。
- 开启意图与执行就绪分离。临时故障保持开启意图，检测按认证、TLS、网络、Worker 配置、引擎／GPU、模型、样图和输出分类，错误正文不直接回传。
- JSON Provider 复用文件锁与原子写入；PostgreSQL 独立单例 JSONB 表使用行锁事务。管理读写无进程短缓存。
- 运行连接冻结修订号、服务身份、模型版本／摘要及受控凭据引用；地址和信任变化保留旧连接档案，同连接凭据轮换更新受控引用。新设置不修改旧快照，不自动取消任务或启停服务。
- 样图归 Worker 的固定启动实例自检管理。已有自检只查询和下载；仅管理员显式执行且当前实例尚未开始时才调用原幂等自检入口。未知或失败结果不创建替代推理任务。
- 当前自检所用模型必须与选择的模型及版本／摘要一致；仅能力列表出现不足以首次开启。完整下载后再次检查启动实例、样图身份与资格，防止重启期间借用旧证明。
