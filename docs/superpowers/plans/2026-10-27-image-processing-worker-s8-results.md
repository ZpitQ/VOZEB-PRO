## 失败原因与修复

大像素商品参考直接提交触发上游invalid_image_file。主输入的受控对照中，原尺寸重新编码或去掉蒙版仍被拒绝，等比缩小参考及配套蒙版后成功；副参考对照只替换第二张图片为等比副本后成功。供应商精确像素或编码字节阈值仍未知，未将本轮拟合尺寸定义为通用上限。

后续等待发生在内部完成登记：生成副本已经上传，HTTP入口仍仅接受analysis或mask作为首工件，因此拒绝合法单个generation_reference。修复该类别与几何校验后，原M轮自然完成，无需重新发送需求或补做增强。回归改为经过真实上传及完成Route，再校验最终TCP提交，补齐原服务层测试遗漏的入口边界。

相关File和独立单连接池PostgreSQL定向回归、类型检查、静态检查、固定镜像构建及真实M轮分别通过。原工具失败、夹具错误、中断和历史上游失败保留各自记录，不混作一次全量通过。

## PR 回归补充：WebP 来源准入

完整浏览器回归发现，上传接口接受的 WebP 原件在 `prepare_reference` 阶段因资源模型未覆盖该布局而暂停，父任务尚未进入视觉分析。独立数据库回读确认 `profile_uncalibrated`，未把等待时间误判为模型耗时，也未通过修改夹具格式或延长超时绕过问题。

以 Sharp 0.35.5 对 8000×8000 的 RGB/RGBA8 WebP 噪声商品图完成 19 项独立监督进程／子进程测量，分别记录 child RSS、heap、external 与 cgroup peak/events，所有进程正常退出、无 OOM。分析峰值超过原 PNG/JPEG 分析预留，因此 WebP 分析采用 `140MiB + 8 × 64MP + 4MiB + 4 × 2048²`，按 MiB 向上取整为 649MiB；生成副本、保护、取证及场景合成继续按各自测量和原工作空间计价。

新增准入仅覆盖 WebP 原件的分析、生成副本、白底／局部／选区保护、完整／裁片取证，以及有完整尺寸检查点且最多 64MP 的局部场景合成来源。原件摘要与保护坐标继续保留；上游原生结果、分层和增强输入没有借用 WebP 来源资格。所测样本均在既有 20MiB 输入域内，工程预留不能视为所有 WebP 编码或部署配置的绝对内存上界。

资源准入回归先在原实现中重现拒绝，再验证来源角色与预算；真实 CPU 结果保护回归和 Web 类型检查另轮通过。最终桌面回归与全部 Actions 以 PR 最新提交的实际结果收口，历史失败记录保留。已核对 todo 与生产上线基线，此补充不改变原生产容量、GPU 画质或部署验收范围。

## 保留的限制与后续

- 增加容器内存不会自动扩展已校准像素域。超过已测增强容量的输入继续保留原件并进入profile_uncalibrated暂停；64MP副参考准备资格不等同于64MP商品完整保护或增强资格。
- S6的20用户、约62分钟负载及10分钟空闲属于受控上游实测，不代表任意硬件下的真实模型／GPU并发吞吐；其他资源档位需要各自容量证据。
