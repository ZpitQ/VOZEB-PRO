# M5 增量：精细增强（TTA）

## 目标与边界

管理员可以为新增强任务选择 Upscayl 精细增强（TTA），普通用户仍通过一句话创作。默认关闭，模型选择独立。沿用原图先交付、异步增强及失败保留原图；不增加新的生图或增强队列。

TTA 对同一输入执行多路变换推理后融合，可能改善细节和纹理一致性，也会增加处理时间；不能承诺所有图片都更好。真实家居图片开关对比与自动功能验收分别记录。

## 实施顺序

1. Worker：模型能力发布 `ttaModes: [false, true]`；请求允许显式布尔 `tta`，冻结模式进入策略、计划和幂等身份；Windows 原生载荷保留布尔值，仅开启时追加一次 `-x`。
2. 后台与业务：持久化精细增强开关，保存后立即读回与刷新一致；按远程模型能力校验，任务冻结模式，恢复和重试不读取新的全局默认。日志展示任务冻结模式与已有执行耗时。
3. 候选验证：更新 Windows Worker 后，同一真实图片、同模型、同尺寸、同 tile 做开启和关闭对比；再发布经审查的开发构建。真实画质由人工验收，默认策略不自动改为开启。

旧 Worker 没有声明 TTA 能力时只允许普通增强。禁止静默忽略开启请求；普通模式请求仍按旧协议发送，不用新增字段破坏其严格校验。服务样图自检继续每次启动唯一的 GPU 校准，不能冒充 TTA 画质验收。

远端计划还须冻结请求字段的存在性：旧普通请求不携带 `tta`，能力升级后恢复也不能添加 `tta:false`。否则已接受但丢回包的任务会因幂等指纹变化而冲突。恢复沿原键和原请求，不换键重建任务。

HTTP 请求超时与 GPU 执行期限分开管理，保留原管理员配置，不通过固定倍数或额外自动重试掩盖耗时。仅执行受影响的桌面、协议及 Windows 原生定向验证，不重跑无关安装或权限矩阵。
